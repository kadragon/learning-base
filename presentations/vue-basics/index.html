THE MANIFEST

package.json — 프로젝트의 명세서

uniweb/package.json — 발췌
{
  "engines": {
    "node": "^24.13.0",
    "pnpm": "^11.1.3"
  },
  "packageManager": "pnpm@11.1.3",
  "scripts": {
    "dev": "vite --mode dev --host",
    "type-check": "vue-tsc --noEmit"
  }
}

스크립트 16개 중 2개만, dependencies·devDependencies는 생략한 발췌입니다 · JSON에는 주석을 쓸 수 없어 생략 표시를 파일 안에 넣지 않았습니다

engines이 프로젝트가 요구하는 런타임 버전

packageManager패키지 매니저 자체를 한 버전으로 고정

scripts팀이 합의한 명령의 이름표 — pnpm dev가 실제로 무엇인지

npm 문서 기준 engines는 engine-strict 설정이 없으면 경고만 냅니다 · 강제하려면 별도 설정이 필요합니다

VERSION RANGES

버전이 아니라 범위를 적습니다

^3.5.27

minor · patch 올라가는 건 허용

3.5.27 → 3.9.0 ✅   4.0.0 ❌

vue가 이 방식입니다

~5.9.3

patch만 허용

5.9.3 → 5.9.9 ✅   5.10.0 ❌

typescript가 이 방식입니다 — 마이너 업데이트로도 타입 검사 결과가 바뀔 수 있어서

package.json은 범위, lockfile은 딱 하나 · 그래서 같은 package.json으로도 설치 결과가 달라질 수 있고, lockfile이 그걸 막습니다

npm 문서의 semver 표기 기준 — ^는 minor·patch, ~는 patch까지 허용

LOCKFILE & NODE_MODULES

하나는 반드시 커밋하고, 하나는 절대 커밋하지 않습니다

커밋

pnpm-lock.yaml

각 패키지가 정확히 어떤 버전으로 설치됐는지 기록한 파일. 이게 있어야 내 노트북과 CI가 같은 걸 설치합니다.

커밋 금지

node_modules/

lockfile로부터 언제든 다시 만들 수 있는 결과물. 지워도 됩니다 — pnpm install로 복구됩니다.

“You should always commit the lockfile (pnpm-lock.yaml).” pnpm.io — Working with Git

이상하면 node_modules를 지우고 다시 설치하세요 · 그게 안전한 이유가 바로 이 구분입니다

13

WHY PNPM

이 팀이 npm 대신 pnpm을 쓰는 이유

디스크에 한 번만

같은 패키지를 프로젝트마다 복사하지 않고, 한 곳(content-addressable store)에 저장합니다.

“all the files are saved in a single place on the disk”

선언한 것만 보입니다

node_modules 최상단에는 직접 선언한 의존성만 심볼릭 링크로 올라옵니다.

“By default, pnpm uses symlinks to add only the direct dependencies of the project into the root of the modules directory”

기본 설정에서는 package.json에 적지 않은 패키지가 import되지 않습니다 · npm에서는 다른 패키지가 끌어온 것까지 우연히 import되곤 합니다

속도가 아니라 엄격함으로 기억하세요 · 출처 pnpm.io/motivation

COMMAND MAP

npm 문장을 pnpm으로 읽는 법

npm pnpm 하는 일
npm install pnpm install lockfile대로 전부 설치
npm install <pkg> pnpm add <pkg> 의존성 추가
npm install -D <pkg> pnpm add -D <pkg> 개발용 의존성 추가
npm run <script> pnpm run <script> 스크립트 실행
npx <bin> 설치되어 있으면 pnpm exec <bin> 프로젝트의 node_modules/.bin에 있는 실행 파일
npx <bin> 설치 안 됐으면 pnpm dlx <bin> 레지스트리에서 받아 일회성으로 실행
pnpm dev는 되는데 왜 어떤 건 안 되나 run은 대개 생략됩니다. 단 스크립트 이름이 pnpm 자체 명령과 겹치면 안 됩니다 — 공식 문서 표현으로 “ONLY for scripts that do not share the same name as already existing pnpm commands”. 예: add라는 스크립트는 반드시 pnpm run add

npx가 두 줄인 이유 — npx는 설치 여부에 따라 알아서 갈라지지만, pnpm은 두 명령이 나뉘어 있습니다 · 세상의 문서와 README는 대부분 npm으로 쓰여 있으니 번역해서 읽는 것이 목표입니다

ANNOTATION SYNTAX

//        2. 매개변수마다        3. 괄호 뒤 — 반환값

  return `${name} · ${team}`
}

// 적지 않으면 추론합니다 — total은 number
const total = memberCount * 2

변수이름 뒤에 : 타입

REACTIVE & COMPUTED

나머지 둘은 언제 쓰는지만 알면 됩니다

reactive() — 오늘은 쓰지 않습니다

객체 전용이고, 구조 분해하면 반응성이 끊깁니다.

“Due to these limitations, we recommend using ref() as the primary API for declaring reactive state.”

그래서 오늘 만드는 코드는 전부 ref입니다

computed() — 계산해서 나오는 값

의존하는 값이 바뀔 때만 다시 계산하고, 그 사이에는 결과를 재사용합니다.

“A computed property will only re-evaluate when some of its reactive dependencies have changed.”

메서드로 쓰면 다시 그릴 때마다 매번 실행됩니다 — 문서 표현으로 “always run … whenever a re-render happens”

MemberListView.vue — 검색 결과는 계산된 값입니다
const visibleMembers = computed(() =>
  members.value.filter((member) => {
    const query = keyword.value
    return member.name.includes(query) || member.team.includes(query)
  }),
)

EVENTS UP

자식은 바꾸지 않고, 알립니다

자식 — 올려 보냅니다
const emit = defineEmits<{
  toggleBookmark: [id: number]
}>()

// template
<button type="button" @click="emit('toggleBookmark', member.id)">
  {{ props.isBookmarked ? '★ 즐겨찾기 해제' : '☆ 즐겨찾기' }}
</button>
부모 — 받아서 상태를 바꿉니다
// template — 39번 슬라이드의 그 태그입니다
<MemberCard @toggle-bookmark="toggleBookmark" ... />

// script
function toggleBookmark(id: number) {
  bookmarked.value = bookmarked.value.includes(id)
    ? bookmarked.value.filter((bookmarkedId) => bookmarkedId !== id)
    : [...bookmarked.value, id]
}

부모 → 자식 · props상태를 가진 쪽이 값을 내려보냅니다

자식은 그리기만받은 isBookmarked를 고치지 않습니다

자식 → 부모 · emit“눌렸다”만 올리고, 바꾸는 건 부모가 합니다

props는 아래로, 이벤트는 위로 · 상태를 바꾸는 곳이 한 군데로 모입니다

LIFECYCLE

“화면이 뜬 다음에” 할 일 — onMounted

MemberListView.vue — 데이터는 여기서 들어옵니다
const members = ref<Member[]>([])   // 처음엔 빈 배열

onMounted(async () => {
  const response = await fetch('/members.json')
  members.value = await response.json()
})
“the onMounted hook can be used to run code after the component has finished the initial rendering and created the DOM nodes.” vuejs.org — Lifecycle Hooks

빈 값으로 먼저 그립니다그래서 v-if로 “없을 때 화면”이 필요했습니다

onUnmounted는 치우는 쪽타이머·구독처럼 걸어 둔 것을 여기서 해제합니다

등록은 반드시 setup 안에서조건문이나 await 뒤에서 부르면 안 됩니다 — 문서 표현으로 “synchronously”

지금은 fetch를 화면 파일 안에 두었습니다 · 6장에서 이 블록을 통째로 composable로 옮깁니다 — 상세 페이지도 같은 데이터가 필요해지기 때문입니다
