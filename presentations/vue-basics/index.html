THE MANIFEST

package.json — 프로젝트의 명세서

uniweb/package.json — 발췌
{
  "engines": {
    "node": "^24.13.0",
    "pnpm": "^11.1.3"
  },
  "packageManager": "pnpm@11.1.3",
  "scripts": {
    "dev": "vite --mode dev --host",
    "type-check": "vue-tsc --noEmit",   // 전체 16개 중 2개
  },
  // "dependencies", "devDependencies" 생략 — 다음 장에서
}

engines이 프로젝트가 요구하는 런타임 버전

packageManager패키지 매니저 자체를 한 버전으로 고정

scripts팀이 합의한 명령의 이름표 — pnpm dev가 실제로 무엇인지

npm 문서 기준 engines는 engine-strict 설정이 없으면 경고만 냅니다 · 강제하려면 별도 설정이 필요합니다

11

VERSION RANGES

버전이 아니라 범위를 적습니다

^3.5.27

minor · patch 올라가는 건 허용

3.5.27 → 3.9.0 ✅   4.0.0 ❌

vue가 이 방식입니다

~5.9.3

patch만 허용

5.9.3 → 5.9.9 ✅   5.10.0 ❌

typescript가 이 방식입니다 — 마이너 업데이트로도 타입 검사 결과가 바뀔 수 있어서

package.json은 범위, lockfile은 딱 하나 · 그래서 같은 package.json으로도 설치 결과가 달라질 수 있고, lockfile이 그걸 막습니다

npm 문서의 semver 표기 기준 — ^는 minor·patch, ~는 patch까지 허용

12

LOCKFILE & NODE_MODULES

하나는 반드시 커밋하고, 하나는 절대 커밋하지 않습니다

커밋

pnpm-lock.yaml

각 패키지가 정확히 어떤 버전으로 설치됐는지 기록한 파일. 이게 있어야 내 노트북과 CI가 같은 걸 설치합니다.

커밋 금지

node_modules/

lockfile로부터 언제든 다시 만들 수 있는 결과물. 지워도 됩니다 — pnpm install로 복구됩니다.

“You should always commit the lockfile (pnpm-lock.yaml).” pnpm.io — Working with Git

이상하면 node_modules를 지우고 다시 설치하세요 · 그게 안전한 이유가 바로 이 구분입니다

13

WHY PNPM

이 팀이 npm 대신 pnpm을 쓰는 이유

디스크에 한 번만

같은 패키지를 프로젝트마다 복사하지 않고, 한 곳(content-addressable store)에 저장합니다.

“all the files are saved in a single place on the disk”

선언한 것만 보입니다

node_modules 최상단에는 직접 선언한 의존성만 심볼릭 링크로 올라옵니다.

“pnpm uses symlinks to add only the direct dependencies of the project into the root of the modules directory”

기본 설정에서는 package.json에 적지 않은 패키지가 import되지 않습니다 · npm에서는 다른 패키지가 끌어온 것까지 우연히 import되곤 합니다

속도가 아니라 엄격함으로 기억하세요 · 출처 pnpm.io/motivation

14

COMMAND MAP

npm 문장을 pnpm으로 읽는 법

npm pnpm 하는 일
npm install pnpm install lockfile대로 전부 설치
npm install <pkg> pnpm add <pkg> 의존성 추가
npm install -D <pkg> pnpm add -D <pkg> 개발용 의존성 추가
npm run <script> pnpm run <script> 스크립트 실행
npx <bin> pnpm dlx <bin> 설치 없이 일회성 실행
pnpm dev는 되는데 왜 어떤 건 안 되나 run은 대개 생략됩니다. 단 스크립트 이름이 pnpm 자체 명령과 겹치면 안 됩니다 — 공식 문서 표현으로 “ONLY for scripts that do not share the same name as already existing pnpm commands”. 예: add라는 스크립트는 반드시 pnpm run add

세상의 문서와 README는 대부분 npm으로 쓰여 있습니다 · 가려서 쓰는 게 아니라 번역해서 읽는 것이 목표입니다

THE VERSION PIN

버전은 세 군데에서 고정됩니다

package.json → engines.node ^24.13.0 이 저장소가 요구하는 Node
package.json → packageManager pnpm@11.1.3 패키지 매니저 버전까지 고정
.nvmrc 첫 줄 24.13.0 nvm use가 읽어서 런타임을 바꿔 줍니다
uniweb 저장소 안에서
$ nvm use          # .nvmrc 첫 줄의 버전으로 전환
$ node --version    # v24.13.0 인지 확인
$ pnpm --version    # 11.1.3 이상인지 확인

강의 전 체크리스트가 Node 24.13.0을 못 박은 이유입니다 · 출력값은 각자 환경에 따라 다를 수 있으니 직접 확인하세요
